# 📐 Engenharia de Software II

Este repositório reúne dois documentos acadêmicos dedicados à **análise e especificação de requisitos de sistemas**. Os materiais mostram como identificar e documentar as necessidades de um sistema antes de sua implementação, descrevendo funcionalidades, objetivos e características esperadas.

## 📂 Documentos disponíveis

| Documento | Assunto |
|---|---|
| [01 — Modelo de Documentação de Sistema](01-Modelo%20de%20Documenta%C3%A7%C3%A3o%20de%20Sistema.docx) | Especificação de um aplicativo bancário, com cadastro e acesso à conta, Pix, pagamentos e comprovantes. |
| [02 — Modelo de Documentação de Sistema](01-Modelo%20de%20Documenta%C3%A7%C3%A3o%20de%20Sistema_2.docx) | Proposta de um sistema para cadastrar, consultar, editar e excluir receitas. |

## 📝 O que os materiais abordam

Os documentos exploram a definição do **escopo de um sistema** e a descrição dos recursos esperados pelo usuário. Também apresentam requisitos relacionados à experiência de uso, ao armazenamento de dados, à segurança e ao desempenho, conforme o contexto de cada proposta.

A organização utiliza identificadores para diferenciar tipos de requisito:

| Identificação | Significado |
|---|---|
| `RF` | Requisito funcional: o que o sistema deve fazer. |
| `RNFR` | Requisito não funcional relacionado a uma funcionalidade. |
| `RNFS` | Requisito não funcional aplicável ao sistema como um todo. |

## 🎯 Finalidade dos estudos

O foco é praticar a **transformação de uma ideia em requisitos documentados**, deixando claro o que se espera do software e criando uma base para as próximas etapas do desenvolvimento.

Os arquivos estão em formato **Word (`.docx`)** e descrevem propostas de sistemas, não aplicações implementadas neste repositório.
